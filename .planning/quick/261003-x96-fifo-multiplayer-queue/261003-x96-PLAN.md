# Quick Plan: Multi-player FIFO Queue for Scammer NPC

## Objective
Connect and fully activate the server-side FIFO queue arbiter for multiple players approaching MatiBuilds (the scammer NPC).
When multiple players enter the notice range (28 studs):
1. The first player to arrive becomes the active owner; Mati approaches and interacts with them.
2. Subsequent players arriving within 28 studs are deduplicated and enqueued in FIFO order with `UserId` tie-break per D-24.
3. If an enqueued player leaves the area (> 32 studs), disconnects, or dies, they are pruned from the queue.
4. When the current encounter completes (or breaks / cancels), the next eligible player in the FIFO queue is automatically popped and Mati navigates to them next.
5. If the queue is empty, Mati resumes idle patrol.

## Tasks
1. **NPCNavigation Arbiter Enhancements**:
   - Add `isInQueue(player: Player): boolean` and `getQueue(): { Player }` to `Arbiter`.
   - In `advanceQueue()`, verify character is alive (`Humanoid.Health > 0`) and has `HumanoidRootPart`.
2. **ScammerNPCManager Integration**:
   - Separate continuous player proximity scanning from the single-owner navigation worker loop.
   - Continuous scanner detects eligible players within `NOTICE_DISTANCE` (28 studs):
     - If no current owner, claims and signals worker.
     - If Mati is currently busy, enqueues player into FIFO queue.
     - Prunes players from queue if they move beyond `BREAK_DISTANCE` (32 studs).
   - Worker loop processes current owner -> moves -> anchors -> chats -> releases -> advances queue.
