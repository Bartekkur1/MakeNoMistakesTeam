**Result and discrepancy behavior (D-05–D-08, D-15):** resolve keyed rules through `STRINGS`; never display raw IDs or `undefined`. A credential warning recognized in the message remains even if a contradictory child answer is kept. Correction changes the answer and reevaluates; retention acknowledges only that question's current choices and leaves uncertainty visible. Selecting Nie wiem adds missing information without an accusation. Signals can be multiple; the recommended step is always singular, using the implemented priority: credentials → payment with pressure → prize with link → urgency → independent checking. The action is an instruction, not a button that visits a supplied link. Popraw odpowiedzi and future edit/replacement controls are navigation, not extra recommended steps.

## Spacing Scale

Declared values are existing literal CSS values, not new custom properties. Preserve the implemented scale rather than add unused template defaults.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | `.question-option` vertical margins, `.steps li` margins, badge top margin; hide offset is −4px |
| sm | 8px | Field/option padding, menu/row/label gaps, h2 vertical margin, section-heading bottom margin; panel viewport edge margin |
| compact | 12px | Button horizontal padding, notice padding, row top margin, intro/legend separation, result-step padding; panel-to-avatar gap in positioning |
| md | 16px | Panel padding, result-section separation; viewport width allowance |
| inset | 20px | List indentation; also panel radius, not an extra section gap |
| viewport-y | 32px | Panel max-height allowance: `calc(100vh - 32px)` |

Exceptions already present: native choice inputs have `margin: 2px 0`; badge padding is `2px 6px`, radius 6px and left margin 26px (aligned after 18px control + 8px label gap); result list/paragraph margins are 6px; borders are 1px; focus outline is 3px with 2px offset. Do not silently normalize these into a different grid. Buttons, fields, options, notices and result-step use 12px radii; `.panel` explicitly sets `--radius-widget: 20px` through `:host`. Avatar is 64px; hide target 24px; textarea minimum height 96px with vertical resizing.

Panel width is 320px, max-width `calc(100vw - 16px)`, max-height `calc(100vh - 32px)`, border-box and `overflow: auto`. At a **280px viewport**, outer width is at most 264px and content width about 230px after padding/border. Placement uses 8px edge margins and a 12px avatar gap, prefers above the shark, falls below if needed, then clamps to the viewport. Retain vertical scrolling and reachable controls. No new full-screen/mobile layout is introduced.

Native arrow-key radio navigation and Space checkbox selection remain available. Safety focuses Dalej; preview/paste focus the textarea; menu/how-to focus their first body button; result currently focuses Popraw odpowiedzi. In questions, rendering remembers the active input ID, then focuses that matching input, a checked input, or the first input. This retains focus but recreates controls on answer render; it does not promise DOM identity across renders. Discrepancy is an alert, with keyboard-reachable correction/retention buttons; result section headings name their regions through `aria-labelledby`.

Dragging is different: avatar pointer movement calls `panel.place()` only, so it must retain the actual control node, focus, choice and text/caret throughout the movement. The visible shark and panel move together before pointerup; releasing a drag neither activates the avatar nor captures a selection. Current resize handling calls `render()` and can recreate controls; do not extend the drag identity guarantee to resize. At viewport edges and 280px width, all relevant controls must stay reachable through panel scrolling. Existing 3px blue focus outline with 2px offset remains on panel buttons/inputs/textarea; the avatar has its amber outline. Close/hide focus return and screen-reader behavior need the listed UAT, without claiming new mechanics exist.

**Isolation and rendering contract:** `createHost()` creates an open Shadow DOM and converts palette `:root` to `:host`; adopted stylesheets have a style-element fallback. `:host { all: initial }` establishes the font/color/radius baseline; host geometry uses fixed positioning and existing high z-index. Use `createElement`, `textContent` for labels/results/notices and `.value` for supplied form content; never `innerHTML`, HTML interpolation or clickable anchors for a supplied link. Host styling isolates ordinary page CSS, but an open shadow root is readable by the page and ancestor capture-phase keyboard listeners may intercept input. Existing root event stopping protects bubble listeners only. Preserve the documented capture-phase expected-failure limitation; no iframe architecture is added here.

Store draft, approved case, choices, hints, result and replacement candidate only in memory for the current document/tab. Read only a selection captured on deliberate avatar activation, or explicitly pasted text/link; do not monitor selections, read neighboring messages or fetch/open supplied links. A preview/correction never silently substitutes approved content. Rendering resolves localized keys; recognizer normalization affects its matching copy only. The approved text remains the user's supplied content. No disk storage, new dependency or shared-material mutation is required.
