## Contracts and edge disposition

Move the two pure exports from draft.js to projects/widget/src/core/check.js without changing consumer behavior. detectHints(caseOrDraft) returns frozen { sender: answerId[], request: answerId[], verify: answerId[] }; evaluate(answers, hints) returns frozen { summaryKey, signals: signalId[], unknowns: unknownId[], step: { id, explanationKey }, mismatches: { questionId, answerId, messageKey }[] }. Deduplicate and keep deterministic ordering. All IDs are ASCII; all display copy remains in strings.pl.js. Matching patterns in check.js use Unicode escapes where necessary; source-scan allowlist stays intact. No score, probability, verified identity or URL-reputation service.

Priority is credentials → payment with pressure → prize with link → urgency → independent verification. A standalone payment answer warrants cautious verification rather than an accusation. Independent verification means a known channel reached outside the received message, never the supplied link. Unknown sender and message_link/no_channel add missing information, not automatic fraud signals. Affirmative password/code child answers still produce warnings even if text recognition misses them. Recognition of credentials remains visible even with contradictory answers. No inference of “official” solely from names, brand spelling or a hostname.

The supplied CHK-03 empty and encoding probe rows are resolved explicit by frontmatter truths and task 2 tests. CHK-01 and CHK-02 unclassified rows remain flagged unresolved as recorded in 02-01. Normalizing only a matching copy never rewrites approved content. This rule engine describes evidence and limits, not message truth.

Dependency graph: task 1 needs 02-01's reachable renderer/session, creates credential warning path and extracted engine; task 2 expands rule contracts through the existing UI; task 3 tests the remaining real scenarios and documents the reviewable pack. has_checkpoint=false for all. Tracer verification passes before expansion. Task 1 has a bounded six-file exception: five existing slice files plus main.js callback glue needed for the same retain-answer tracer. The controller change only forwards the keep argument and renders; no new controller feature or subsystem is introduced. The plan stays at nine files overall.
