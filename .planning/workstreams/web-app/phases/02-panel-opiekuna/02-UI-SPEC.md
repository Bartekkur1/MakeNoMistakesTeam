# Phase 02: Panel opiekuna. UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Scope: three routes in `web-app/` (Next.js 16.3.8, React 19.2.8, Tailwind 4.3.3): `/login`, `/panel`, `/panel/[id]`. The panel only calls the phase 1 API with a `panel` scope token. The look reuses the landing design (fonts from `src/app/layout.tsx`, tokens from `src/app/globals.css`, buttons from `src/app/_landing/styles.ts`). All visible copy is Polish.

**Hard constraint (D-02, locked):** nothing in the panel UI marks the app as a demo. No "demo" badge, no hint about the code, no list of demo accounts, no "Wersja demonstracyjna" footer. This includes stripping the `(demo)` / `(smoke)` suffix from display names (see "Display names" below).

## Spacing Scale

Declared values (multiples of 4; Tailwind 4 default spacing, 1 unit = 4px):

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | `1` | Badge vertical padding, gap between a badge and its dot, field error padding-y |
| sm | 8px | `2` | Label to input, gap between stacked action buttons, gap between badges in a row |
| md | 16px | `4` | Page horizontal padding (mobile), card padding (mobile), list row padding, gap between dialog buttons, section heading to content |
| lg | 24px | `6` | Card padding (md+), gap between fields in a form, gap between timeline entries, list row padding-x (md+) |
| xl | 32px | `8` | Gap between cards/columns on detail (lg), page padding-y (mobile), login card padding |
| 2xl | 48px | `12` | Page padding-y (md+) |
| 3xl | 64px | `16` | Header height (`h-16`), login card offset from top (md+) |

Exceptions:
- 12px horizontal padding inside pill badges (`px-3`), matching the landing chips in `Scams.tsx`.
- 12px horizontal padding inside the native state filter `<select>` (`px-3`). Reason: the select is a 40px-high control (`buttonSmall` height) with `text-sm`; 12px keeps the same inner padding as the 14px badges next to it and leaves room for the native dropdown arrow inside the narrow toolbar on 320px screens. Text inputs keep 16px (`px-4`).
- 12px timeline marker size (`size-3`); this is an element size, not a gap.
- 31px negative left margin on the timeline marker (`-ml-[31px]`). Reason: geometry, not spacing. It centers the 12px marker on the 2px track: 24px list padding (`pl-6`) + 2px track (`border-l-2`) + 5px (half the marker minus half the track: 6 - 1). Changing `pl-6` or the marker size requires recomputing this value; no other element uses it.
- Control heights: 40px (`buttonSmall`, select) and 48px (`buttonLarge`, text inputs). Minimum touch target in the panel is 40px; primary form buttons on mobile use 48px.
- Sticky actions card offset `lg:top-24` (96px = 64px header + 32px).

## Interaction Contract

### Session (D-05..D-08, CONTRACT "token nie jest ciasteczkiem")

- Token, `expires_at`, `account` and `children` from the login response are kept in browser storage, never in a cookie and never in the URL (contract). Decision (user, 2026-10-03, ui-phase): one shared session in `localStorage` (survives closing the tab, D-07). A new login in any tab replaces the stored session for the whole browser. "Wyloguj się" clears it. Consequence for the presentation: the parent and teacher windows must run in two separate browsers or browser profiles (or one normal and one private window), not two windows of the same profile.
- A session whose `expires_at` is in the past is discarded without a network call.
- `/panel*` without a valid session: `router.replace("/login")`. `/login` with a valid session: `router.replace("/panel")`.
- Any API 401 (`unauthorized`) inside the panel: clear the session, go to `/login`, show the session-expired banner (pass the reason through `sessionStorage`, not the URL).
- Logout: no confirmation, no API call; clear the session, go to `/login`, show the logged-out banner.

### Login (two steps, D-05, D-06)

1. Step 1 collects the e-mail only, no request. Client check: trimmed value not empty and matches `^[^\s@]+@[^\s@]+$`; `maxLength={LIMITS.emailMaxChars}`, `type="email"`, `autoComplete="email"`, form `noValidate`. Any well-formed e-mail goes to step 2 (an unknown address is not detected here, D-06).
2. Step 2 shows the code field (`autoComplete="one-time-code"`, `inputMode="numeric"`, `maxLength={LIMITS.codeMaxChars}`), focused on entry. "Zaloguj się" sends `POST /api/auth/login` with `{ email, code, scope: "panel" }`. While pending the button reads "Logowanie…", is disabled and has `aria-busy="true"`.
3. On 401 `invalid_credentials`: field error under the code input with the contract message, code cleared and refocused, e-mail kept. Same message for unknown e-mail and wrong code (D-06).
4. "Zmień adres e-mail" returns to step 1 with the e-mail prefilled and focused.
5. On 200: store session, `router.replace("/panel")`.

### List (`/panel`)

- Initial load: `GET /api/reports?limit=20` (plus `&state=` when filtered). Skeleton while loading.
- Filter change: reload from the first page; keep the old rows visible with `aria-busy="true"` on the list until the response arrives.
- "Odśwież listę" (D-14): reload from the first page (drops extra pages loaded by "Pokaż więcej zgłoszeń"), button reads "Odświeżanie…" and is disabled meanwhile; on success update "Odświeżono HH:MM" and announce "Lista odświeżona." in the page's polite live region.
- "Pokaż więcej zgłoszeń" (D-11): `GET /api/reports?limit=20&cursor={next_cursor}` (cursor taken verbatim), append below. Button reads "Wczytywanie…" and is disabled meanwhile. After append, move focus to the first newly added row link and announce "Wczytano kolejne zgłoszenia.". Hide the button when `next_cursor` is `null`.
- No automatic polling (D-14).

### Detail (`/panel/[id]`)

- Load: `GET /api/reports/{id}`. Skeleton while loading.
- Action buttons = `availableActions(report.state, account.role)` only (D-12). If the list is empty, show the no-actions text instead of buttons.
- Clicking an action opens the dialog. Confirm sends `POST /api/reports/{id}/transitions` with `{ action, comment }` (`comment` = trimmed text or `null` when blank).
  - Escalate: blank note blocks the request client-side with the field error and refocuses the field (`TRANSITION_COMMENT_REQUIRED.escalate`). The confirm button is not disabled up front.
  - Pending: confirm reads "Zapisywanie…", both buttons (confirm and "Zostaw bez zmian") disabled, Esc ignored (prevent the dialog `cancel` event), so the dialog cannot close while the result is unknown.
  - 201: close dialog, refetch the detail (`GET /api/reports/{id}`), show the success banner in the "Zmień stan" card and announce it. Nothing is shown as saved before the 201 (CONTRACT "Potwierdzenie zapisu").
  - 409 `invalid_transition` (D-15): close the dialog, show the 409 warning banner at the top of the page, refetch the detail so the buttons match the new state. If the user had typed a note, move it into the new-comment textarea (not sent) so the text is not lost.
  - 404: replace the page with the not-found state (e.g. the parent re-rejected and the teacher lost access).
  - 401: session flow above.
  - 400 `validation_error`: show `details[].message` under the textarea; dialog stays open.
  - 503 / 500 / 403 / network failure: error alert inside the dialog, text preserved, buttons re-enabled so the user can retry (transitions are safe to repeat: a duplicate gets 409).
- New comment: `POST /api/reports/{id}/comments` with `{ body }`. Blank (after trim) is blocked client-side with a field error. Pending: "Wysyłanie…", button disabled, textarea read-only. 201: clear the textarea, append the returned comment to the timeline, announce "Komentarz dodany.". Errors keep the text in the field. Comments are not idempotent, so there is no automatic retry and the network-failure message tells the user to check the timeline first.
- "Odśwież zgłoszenie": refetch the detail; keep the current view during the request; keep any unsent comment draft; update "Odświeżono HH:MM"; announce "Zgłoszenie odświeżone.".

### Formatting helpers

- Dates: `Intl.DateTimeFormat("pl-PL", { day: "numeric", month: "short", year: "numeric", hour: "2-digit", minute: "2-digit", timeZone: "Europe/Warsaw" })`, e.g. "3 paź 2026, 10:30". Always inside `<time dateTime={iso}>`. "Odświeżono HH:MM" uses `hour`/`minute` only.
- Display names: `displayName(name)` removes a trailing ` (demo)` or ` (smoke)` (regex `/\s*\((demo|smoke)\)$/`). Applied to the header account name, child names and timeline authors (D-02). Child name lookup: `DEMO_CHILDREN` by `child_id`, then session `children`, fallback "Dziecko". Author lookup: `findDemoAccountById(actor_id)` for parent/teacher, child via the child lookup; fallback = capitalized role label.
- Capitalize first letter for contract labels that start a line or a button (contract labels are lowercase).

### Accessibility

- One `<h1>` per view; sections use `<h2>`; landmarks `<header>`, `<main>`.
- One polite live region per page (`role="status"`, `sr-only` when it only carries announcements).
- Every input has a visible `<label>`; errors use `aria-describedby` + `aria-invalid`.
- Skeletons: `motion-safe:animate-pulse` (no animation with reduced motion) plus an `sr-only` loading text.
- Focus ring on every interactive element (`outline-2 outline-offset-2 outline-shark-blue`).
- Report content and comments are rendered as text (React escaping); never `dangerouslySetInnerHTML`, never auto-linked.
