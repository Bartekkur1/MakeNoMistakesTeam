| get-case | GET /api/cases/{id} | 200; same content; replies [] |
| list-case | GET /api/cases?demo_child_id=demo-smoke | 200; cases contains the id |
| add-reply | POST /api/cases/{id}/replies {message "Odpowiedź testowa (smoke)."} | 201; case_id equals id |
| status-in-progress | PATCH /api/cases/{id} {status "in_progress"} | 200; status in_progress |
| status-closed | PATCH {status "closed"} | 200; status closed |
| get-final | GET detail | status "closed"; exactly one reply with that message |
| validation-400 | POST /api/cases with content "   " | 400; error.code "validation_error" |
| not-found-404 | GET /api/cases/00000000-0000-4000-8000-000000000000 | 404; error.code "case_not_found" |

Reason formats:
- A network or timeout error on any step → `FAIL <step>: backend unreachable (<error code or name>)`.
- An unexpected status with a JSON error body → `FAIL <step>: <status> <error.code>`.

Last line: `SMOKE OK (<base>)` with exit 0, or `SMOKE FAILED (<base>)` with exit 1. Uncaught exceptions must be caught and reported the same way; never print a stack trace.
