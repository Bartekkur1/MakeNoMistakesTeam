# Landing BezpiecznaAura Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Zastąpić szablonową stronę `/` w `web-app` statycznym, przekonującym landingiem BezpiecznaAura dla rodziców, opiekunów i nauczycieli.

**Architecture:** `src/app/page.tsx` składa 11 sekcji-komponentów z folderu `src/app/_landing/` (podkreślnik = nie tworzy trasy). Wszystkie teksty, liczby, linki i filtr kont demo są w jednym `src/app/_landing/content.ts`, testowanym vitestem. Same Server Components — zero JS po stronie klienta; nawigacja kotwicami, FAQ i źródła na `<details>`.

**Tech Stack:** Next 16.3 (App Router), React 19.2, Tailwind CSS 4 (`@theme` w CSS, bez `tailwind.config.js`), TypeScript, vitest 4.

**Spec:** `docs/superpowers/specs/2026-10-03-landing-design.md`

## Global Constraints

- Zakres wyłącznie landing `/`: nie tworzyć `/login`, nie ruszać API, nie usuwać plików szablonu z `public/` (`next.svg`, `vercel.svg` itd.).
- Bez nowych zależności npm.
- Bez `"use client"` — każdy komponent landingu jest Server Componentem.
- Język polski, polskie cudzysłowy „…”, zwracamy się do rodzica na „Ty”.
- Żadnych zmyślonych opinii, logotypów, liczby użytkowników ani obietnic skuteczności; liczby tylko z `content.ts` ze źródłem.
- Konta demo wyłącznie przez import z `src/lib/contract/demo-accounts.ts` — nie kopiować e-maili do `content.ts`.
- Link pobrania: `https://github.com/Bartekkur1/MakeNoMistakesTeam/releases/latest/download/bezpiecznaaura-wtyczka.zip`; wszystkie wersje: `https://github.com/Bartekkur1/MakeNoMistakesTeam/releases`; logowanie: `/login`.
- `chrome://extensions` tylko jako tekst do skopiowania, nigdy jako `href`.
- Linki zewnętrzne: `target="_blank" rel="noopener noreferrer"`.
- Kolory alarmowe (`siren-amber`, `hook-crimson`) wyłącznie jako akcent (obramowanie/tło), nigdy jako kolor tekstu.
- **Git:** zgodnie z globalnymi instrukcjami użytkownika żadnych komend git bez jego wyraźnej prośby w danej wiadomości. Kroki „Checkpoint” poniżej to propozycje commitów — wykonaj je tylko, jeśli użytkownik o to poprosi.
- Wszystkie komendy uruchamiać w katalogu `web-app/`.

## Review Focus

Brak w repo infrastruktury do testów DOM (vitest działa w `environment: "node"`, `include: tests/**/*.test.ts`), a spec zabrania nowych zależności — dlatego te punkty są przypięte jako jawne kontrole ręczne w Task 6 albo testami treści w Task 1:

1. **Telefon 360–375 px** — brak poziomego przewijania; długie e-maile kont demo i `chrome://extensions` łamią się (`break-all`) zamiast rozpychać stronę. → Task 6, krok 4.
2. **Kotwice pod przyklejonym nagłówkiem** — po kliknięciu „Jak to działa”, „Dla rodziców” itd. nagłówek sekcji nie chowa się pod paskiem (`scroll-mt-20`). Każdy link nawigacji musi wskazywać istniejące `id`. → test „points every nav link at a section anchor” w Task 1 + Task 6, krok 4.
3. **`chrome://extensions` jako link** — Chrome blokuje taką nawigację, więc musi być tekstem do zaznaczenia. → test „shows chrome://extensions as copyable text in exactly one install step” w Task 1 + Task 6, krok 4.
4. **Konta „(smoke)” na stronie** — nie mogą trafić do ramki demo. → test „hides smoke-test accounts” w Task 1.
5. **Nawigacja klawiaturą** — Tab przechodzi przez linki, przyciski i `<summary>` FAQ z widocznym obrysem focus. → Task 6, krok 4.

    const accounts = presentableDemoAccounts();

    expect(accounts.some((account) => account.display_name.includes("(smoke)"))).toBe(false);
    expect(accounts.filter((account) => account.role === "parent")).toHaveLength(3);
    expect(accounts.filter((account) => account.role === "teacher")).toHaveLength(2);

  it("gives every stat a value, label and source", () => {
    expect(STATS).toHaveLength(3);
    for (const stat of STATS) {
      expect(stat.value.trim()).not.toBe("");
      expect(stat.label.trim()).not.toBe("");
      expect(stat.source.trim()).not.toBe("");
    }
  });

  it("lists every cited source once in the footer sources", () => {
    const cited = [...STATS.map((stat) => stat.source), TRAINING_FACT.source];

    for (const source of cited) {
      expect(SOURCES).toContain(source);
    }
    expect(new Set(SOURCES).size).toBe(SOURCES.length);
  });

  it("downloads the extension zip from the latest GitHub release", () => {
    expect(RELEASES_URL).toBe("https://github.com/Bartekkur1/MakeNoMistakesTeam/releases");
    expect(EXTENSION_DOWNLOAD_URL).toBe(`${RELEASES_URL}/latest/download/bezpiecznaaura-wtyczka.zip`);
  });

  it("answers every FAQ question", () => {
    expect(FAQ.items).toHaveLength(6);
    for (const item of FAQ.items) {
      expect(item.question.trim()).not.toBe("");
      expect(item.answer.trim()).not.toBe("");
    }
  });

  it("shows chrome://extensions as copyable text in exactly one install step", () => {
    const stepsWithCode = INSTALL.steps.filter((step) => step.code !== undefined);

    expect(INSTALL.steps).toHaveLength(5);
    expect(stepsWithCode).toEqual([expect.objectContaining({ code: CHROME_EXTENSIONS_PAGE })]);
    expect(CHROME_EXTENSIONS_PAGE).toBe("chrome://extensions");
  });

  it("points every nav link at a section anchor", () => {
    const anchors = Object.values(SECTION_IDS).map((id) => `#${id}`);

    expect(NAV_LINKS).toHaveLength(4);
    for (const link of NAV_LINKS) {
      expect(anchors).toContain(link.href);
    }
  });
});

interface SectionProps {

  title: string;

  tone?: "white" | "surface";

}

// scroll-mt-20 (5rem) keeps the heading clear of the 4rem sticky header when jumping to an anchor.
export function Section({ id, title, intro, tone = "white", children }: SectionProps) {
  const background = tone === "surface" ? "bg-ice-surface" : "bg-white";

  return (
    <section id={id} className={`scroll-mt-20 px-4 py-16 md:py-24 ${background}`}>

        <div className="mt-10">{children}</div>
      </div>
    </section>
  );
}
